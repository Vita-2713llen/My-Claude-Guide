### ⛔ Кросбраузерність — WebKit, Firefox і Edge реально відкриваються (practice rule, 2026-09-14)

**«Перевірено лише в Chromium» — це не результат, а невиконана перевірка.** Рядок не
закривається, доки сайт не відкрився в кожному рушії.

**Інструмент — `qa-run.cjs`, без власних скриптів.** Chromium (еталон — Chromium зі складу
Playwright, версія закріплена `package-lock`; системний Chrome лише за `"chromium": "chrome"` у
`qa-target.json` або `QA_USE_SYSTEM_CHROME=1`), **WebKit** (рушій Safari), **Firefox** і
**Microsoft Edge** (Playwright channel `msedge` або `EDGE_PATH`). Що саме запустилось і якої
версії — у RUN-07 і в шапці манифесту. Рушії ставляться за `INSTALL.md` (`npm run browsers` у
`scripts/`; на Linux людина ще раз запускає `sudo env "PATH=$PATH" npm run browsers-deps`). `npx playwright install`
не використовувати — він ставить ревізії не під закріплений `playwright-core`. Рушій, що не
стартував, — ⚠️ NOT RUN з причиною й командою, ніколи ✅ і ніколи «перевірено в Chrome». Власний
скрипт на Puppeteer чи інший драйвер заборонено.

**Що проганяється:** кожна сторінка плану (`qa-out/pages.json`: статичні + вибірка з кожного
CMS-шаблону). Chromium — усі тири `widths`; WebKit і Firefox — опорні тири 1440 · 768 · 360
(`"xbWidths": "all"` додає кожен тир нижче 768; які тири лишились лише в Chromium — записано в
RUN-04 і XB-01); Edge — 1440 і 360. На тирах < 768 Chromium і WebKit з `isMobile` + `hasTouch` —
наближення iOS, не iOS. Рушії йдуть по черзі, сторінки в рушії — `concurrency` воркерів (фази
взаємодій — `interactConcurrency` паралельних контекстів, результат той самий, що й по одній).
Стайлгайд не проганяється.

| Вимір (у кожному рушії, на кожній сторінці й ширині) | Знахідка, якщо | ID |
|---|---|---|
| `scrollWidth − clientWidth`, обрізані елементи, шрифти, биті зображення, позиції секцій (±2px) | розбіжність із Chromium | XB-01 |
| Помилки JS і невдалі запити | помилка лише в цьому рушії | XB-01, JS-01 |
| Тогли / FAQ, бургер відкрити-закрити, ховер | стан не змінюється так, як у Chromium | XB-08 |
| Рядки бургера: 6 точок + Enter/Space | хоч одна точка не перемикає | NAV-13 |
| Поля форм: висота, падінги, `line-height`, тип; положення тексту в полі (±2px) | відрізняється від Chromium | FORM-07, FORM-10 |
| Ввід тексту й дат, пікер дати (WebKit, Firefox, iPad-контекст WebKit) | поле не приймає ввід, пікер не відкривається | FORM-11 |
| Перемикач мови | контент, `lang` чи URL не змінились | I18N-03 |
| Повносторінкові скріншоти всіх рушіїв | зберігаються в `qa-out/shots/`; сторінки з числовою різницею переглядаються поруч із Chromium | VIS-01 |

Чого `qa-run` в інших рушіях **не** міряє (і що тоді лишається ⚠️ з маршрутом, а не тихим ✅):
вигляд «на око» поза скріншотами і кількість динамічних карток від зовнішніх сервісів —
переглядаються людиною за скріншотами (VIS-01).

**Пастки, знайдені на перших прогонах — інструмент їх уже враховує, агентові їх не повторювати:**
- **Мобільний WebKit (`isMobile`) не має колеса миші** — прокрутка кроками, а блокування скролу
  під бургером читається зі стилів (`overflow: hidden` на `html`/`body` або `position: fixed`).
- **Ховер читається з кожного вкладеного елемента і їхніх `::before/::after`, разом із
  `transform`.** Замір лише кольору/фону дав колись «ховер не змінюється» в усіх трьох рушіях —
  це була помилка інструмента, не сайту.
- **Різна висота абзацу в Safari — спершу `text-wrap`.** `text-wrap: pretty` Safari розкладає
  власним алгоритмом (часто на рядок більше), Firefox `pretty` не підтримує. Текст цілий і нічого
  не накладається — особливість рушія, не дефект.
- **Шум, який не є знахідкою:** антибот-віджет у headless (postMessage origin,
  `ERR_NAME_NOT_RESOLVED` на хості челенджу, `401` на Private Access Token у WebKit); Firefox
  «Cookie … rejected for invalid domain» на піддомені платформи. JS-01 позначає сторонні збої як ❓.

### Справжній Safari (macOS) — XB-02

`node <skill>/scripts/safari-real.cjs --out qa-out` (з теки проєкту). Адреса — з `qa-target.json`
або `--base` (стадія 1 — `--local <тека збірки>`, той самий 127.0.0.1, що в `qa-run`); сторінки — `qa-out/pages.json` від `qa-run`. Вікна: найбільша десктопна ширина з
`widths`, що вміщається на екран (1440, коли вміщається), і 768; реальний `innerWidth`
записується, бо вужче вікно Safari macOS не стає. Той самий замір `STATIC` з `measure-page.cjs`,
що й у `qa-run`; поля форм порівнюються з Chromium на тому самому `innerWidth` (FORM-07, FORM-10);
скріншоти форм і полів — `qa-out/shots/safari/`.

**Дозвіл вмикає людина:** Safari → Settings → Advanced → Show Develop menu → Develop → **Allow
Remote Automation**. Змінювати налаштування Safari самому не можна. Без дозволу `safari-real.cjs`
сам пише XB-02 NOT RUN з маршрутом — «порт відкрився» нічого не доводить, рядок закривається лише
створеною сесією. Поки її немає, у звіті «WebKit engine», а не «Safari». safaridriver не віддає
console log: помилки консолі в Safari беруться з WebKit-прогону, і звіт це каже.

### ⛔ Якщо QA-машина на Windows чи Linux (practice rule, 2026-10-05)

**ОС визначає, які рядки взагалі можливі** — і RUN-07 це пише. Safari й iOS Simulator існують лише
на macOS (Xcode — лише для macOS, macOS за ліцензією Apple — лише на залізі Apple). Це межа
машини, і прогін її називає, а не замінює рушієм.

| Рядок | Windows / Linux | Як саме |
|---|---|---|
| Chrome | ✅ | Chromium у `qa-run` (системний Chrome — за бажанням, `"chromium": "chrome"`) |
| **Microsoft Edge** | ✅ (Windows — передвстановлений; Linux — людина ставить) | `qa-run`, XB-04. Закривається лише відкритим Edge |
| Firefox, WebKit | ✅ | `qa-run`. WebKit на Windows/Linux — збірка рушія: рядок «Safari» ним **не закривається** |
| Chrome on Android | емулятор Android Studio (образ Google APIs) або пристрій по USB | XB-05; без них — `routed` |
| Safari macOS, Mobile Safari / iOS | ❌ | XB-02, XB-03, LAY-09 → NOT RUN з маршрутом |

**Маршрутизація незакритих рядків — обовʼязкова, «немає Mac» не закриває рядок.** Вибирається
один шлях і записується `record.cjs --status routed --note "хто, яка машина, коли"`:

1. **Mac у команді** — той самий `qa-target.json`, з теки проєкту на Mac: `safari-real.cjs` і
   `ios.cjs` з `--out qa-out`, а результати переносяться в `qa-out` основної машини через
   `record.cjs --import <results-*.json> --tool <назва>` (або `--as <мітка>` для ручних записів).
2. **Віддалений доступ до того Mac** (Screen Sharing чи аналог) — коли QA хоче клікати руками.
   Тільки з відома власника машини.
3. **Хмарна ферма реальних пристроїв** — платна, працює з Windows. ⛔ «Симуляція iPhone» в тих же
   сервісах — **не** реальний пристрій; рядок, закритий симуляцією, лишається ⚠️.
4. **Орендований Mac** або CI-раннер macOS — коли iOS-прогін треба регулярно й без людини.

Тапи й свайпи на віддаленому симуляторі (Appium з драйвером `xcuitest` на Mac і тунель
`ssh -L 4723:127.0.0.1:4723`) — лише як інструмент людини для рядків IOS-*: capability
`appium:webviewConnectTimeout: 60000` обовʼязкова, інакше сесія падає на ~5 с. Встановлює Appium
людина; агент глобальних пакетів не ставить.

### ⛔ iPhone — справжній мобільний Safari в iOS Simulator (practice rule, 2026-09-14)

**WebKit з `isMobile` — це рушій, а не iOS.** Він не показує поведінку, яка існує лише на iPhone:
свайп під відкритим меню, панель адреси Safari, клавіатуру й пікери, липкий ховер після тапу,
safe-area. Тому на кожній перевірці задеплоєного сайту (стадії 2 і 3) сайт відкривається в
**iOS Simulator** — там справжній Mobile Safari.

**Середовище — прогін сам пояснює, як його підняти (practice rule, 2026-10-05).**
«Немає симулятора» не є відповіддю: перший же прогін друкує стан машини й конкретні кроки,
і позначає, які з них потребують пароля людини.

**Крок 0 — що вже є:**

```
xcode-select -p                 # має вказувати на Xcode.app, а не на CommandLineTools
xcrun simctl list runtimes      # має бути хоч один iOS runtime
xcrun simctl list devices available
```

**Якщо Xcode немає** (macOS): Xcode ставиться з App Store (потрібен Apple ID — це крок людини)
або з developer.apple.com/download. Самих Command Line Tools **недостатньо**: `simctl` без Xcode
не має рантаймів. Після встановлення — три команди, перші дві просять пароль, тому їх виконує людина:

```
sudo xcode-select -s /Applications/Xcode.app/Contents/Developer
sudo xcodebuild -runFirstLaunch
xcodebuild -downloadPlatform iOS          # рантайм без App Store
```

**Запуск і керування:**

```
xcrun simctl boot "<назва пристрою зі списку>"
open -a Simulator                          # якщо людина хоче бачити екран
xcrun simctl openurl booted "<url>"
xcrun simctl io booted screenshot shot.png
xcrun simctl io booted recordVideo out.mov
```

Тапи, свайпи й жести — через інструмент керування симулятором, якщо він є в агента (рядки IOS-*);
якщо його немає — людина.

**Якщо машина не на macOS**, симулятора не буде взагалі: Xcode існує лише для macOS, а macOS за
ліцензією Apple працює лише на залізі Apple. Тоді рядок **не закривається «рушієм»**, а
маршрутизується, і маршрут записується в handoff: Mac у команді (Remote Login + ті самі команди
по SSH), орендований Mac у хмарі, хмарна ферма **реальних** пристроїв, або симулятор, який
стрімиться в браузер. Рядок лишається ⚠️ до виконання, ніколи ✅.

Немає Xcode і жодного маршруту — ⚠️ «потрібен Xcode», із надрукованими кроками вище, ніколи ✅.

**Прогін — `ios.cjs`, без проксі й без Homebrew:**

```
node <skill>/scripts/ios.cjs --out qa-out [--local <тека збірки>] [--devices "Назва iPhone,Назва iPad"] [--runtime x.y] [--max 25]
```

(з теки проєкту). Скрипт бере найновіший iOS-рантайм, **найвужчий і найширший iPhone** (ширину
читає з профілю пристрою) і найвужчий iPad ≥768pt, портрет; сам завантажує пристрої й вимикає
лише ті, які завантажив. Щоб кожен Mac міряв ті самі пристрої, закріпити їх у `qa-target.json →
ios` (`iphone`, `ipad`, `runtime`). JS виконується через Web Inspector симулятора
(`appium-remote-debugger` з `scripts/node_modules`, ставиться `npm ci`). Міряє XB-03 (горизонтальний
скрол, обрізання, текст ближче `edgeMinPx` до краю, шрифт полів < 16px нижче 768) і LAY-09
(відступи секцій і елементів проти Playwright WebKit з тим самим вʼюпортом, UA і DPR, ±4px), плюс
доказ FORM-11. Скріншоти — `qa-out/shots/ios/`. Назви пристроїв, рантайм і виміряний `innerWidth`
записуються в манифест.

**Чого `ios.cjs` не робить:** жести (свайп під меню), клавіатура й пікери, landscape, швидкість на
мобільному інтернеті, VoiceOver. Це рядки IOS-01…07 — справжній iPhone, людина (handoff), або
інструмент керування симулятором, якщо він є в агента: тоді результат записується
`record.cjs --id IOS-0x …` з позначкою «симулятор». Без інструмента — не імпровізувати.

Причини NOT RUN, які пише сам скрипт (і лише тоді «міряно скріншотами» допустиме): не macOS;
`xcode-select` вказує на CommandLineTools; немає Xcode; немає iOS-рантайму; закріпленого пристрою
немає (зі списком доступних); `appium-remote-debugger` не встановлений або Node застарий;
`NO_WEBINSPECTOR_SOCKET`; не вдався `openurl`; помилка інспектора; WebKit для LAY-09 не стартував.

| Перевірка на iPhone | Хто | Знахідка, якщо |
|---|---|---|
| Свайп під відкритим бургер-меню, до кінця довгої панелі | IOS-01 (+ CSS-ознаки NAV-09, NAV-15) | сторінка за меню прокрутилась; прокрутка перейшла на сторінку |
| Тап по кнопці, картці, рядку FAQ, потім скріншот | IOS-02 (+ INT-07) | ховер-стан лишився після тапу |
| Висота першого екрана з видимою і згорнутою панеллю Safari; fixed-хедер під час скролу | IOS-03 (+ XB-06) | контент чи кнопка під панеллю; хедер стрибає |
| Фокус на кожному полі, нативний `select`, капча, якщо є | IOS-04 (+ FORM-15) | зум, клавіатура перекрила поле, не той тип клавіатури, пікер не працює |
| Landscape на найширшому доступному iPhone | IOS-05 | контент під вирізом (немає `env(safe-area-inset-*)`), горизонтальний скрол |
| Анімації появи при свайпі вниз і назад | IOS-06 | елемент лишився невидимим або блимнув |
| VoiceOver: хедер, меню, панель | IOS-07 | навігація без назви, кнопка меню без стану, фокус не переходить |
| Скріншоти кожної сторінки плану | `ios.cjs` | переглядаються поруч зі скріншотами WebKit (VIS-01) |

**Справжній iPhone не замінюється симулятором.** Швидкість, реальні жести й антибот-віджет на
пристрої — обовʼязкові рядки handoff для QA-тестувальника (`/qa-check 4`): кабель, Safari →
Develop → [iPhone] → Web Inspector, і перелік IOS-01…07, пройдений руками.

**Ризики, які видно з коду ще до симулятора — читати рядки манифесту першими:** INT-07 (`:hover`
поза `@media (hover: hover)`), XB-06 (`100vh` без `svh`/`dvh`, `-webkit-`-двійники), NAV-15
(панель без `overscroll-behavior`), FORM-15 (поля < 16px), XB-07 (reduced motion, text-size-adjust).
